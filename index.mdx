# Pi

Pi is a minimal terminal coding-agent harness built around a small core and a highly extensible TypeScript ecosystem.

It combines an interactive coding agent, a provider-neutral LLM layer, a reusable agent runtime, a terminal UI library, programmatic SDKs, and extension/package systems in one monorepo.

## What is in this repository?

| Package | Purpose |
| --- | --- |
| `@earendil-works/pi-coding-agent` | Interactive `pi` CLI, sessions, tools, resources, extensions, and SDK |
| `@earendil-works/pi-agent-core` | Agent runtime, tool calling, message/state management |
| `@earendil-works/pi-ai` | Unified model/provider API |
| `@earendil-works/pi-tui` | Terminal UI components and differential rendering |
| `@earendil-works/pi-telemetry` | Vendor-neutral telemetry contracts and adapters |
| `packages/protocol` | Protocol types used by Pi integrations |
| `packages/client` / `packages/server` | Client/server integration layers |
| `packages/session-backends` | Pluggable session persistence backends |

## Core model

Pi runs in the current working directory and gives the model filesystem and shell tools. The default tool set includes `read`, `write`, `edit`, and `bash`; additional built-in read-only tools such as `grep`, `find`, and `ls` can be enabled through tool options.

Project behavior is shaped with `AGENTS.md`, settings, skills, prompt templates, extensions, themes, and Pi packages. Sessions are persisted automatically and can be resumed, forked, cloned, exported, or compacted.

## Security model

Pi does not provide a built-in permission sandbox for filesystem, process, network, or credential access. It runs with the permissions of the user and process that launched it.

Use project trust carefully, keep work under version control, and use a container or sandbox when stronger isolation is required. The repository documents Gondolin, plain Docker, and OpenShell as isolation patterns.
