## What you need

- Three Android camera phones running Android 10 / API 29 or newer
- An optional fourth Android device for the DISPLAY interface
- One shared Wi-Fi network or phone hotspot
- Outdoor access with a clear view of the sky for GNSS timing
- The debug APK from `app/build/outputs/apk/debug/app-debug.apk`

<Warning>
  Install the same APK on every device. The app assigns its initial role from the device model: Pixel to START, Huawei to SPLIT, OnePlus to FINISH, and other devices to DISPLAY.
</Warning>

## Install and connect

<Steps>
  <Step title="Build the APK">
    From the repository root, run:

    ```bash
    ./gradlew assembleDebug
    ```

    On Windows PowerShell or Command Prompt, use:

    ```powershell
    .\gradlew.bat assembleDebug
    ```
  </Step>
  <Step title="Install on every device">
    Install `app/build/outputs/apk/debug/app-debug.apk` on the three timing phones and, optionally, the display device.
  </Step>
  <Step title="Join one network">
    Connect all devices to the same Wi-Fi network or hotspot. The app communicates over UDP port `48123` using broadcast, discovered peers, and local-subnet discovery.
  </Step>
  <Step title="Grant permissions">
    On timing phones, grant Camera and precise Location access. A DISPLAY device does not start camera or GNSS processing.
  </Step>
</Steps>

## Position the timing phones

1. Place the START phone at the starting line.
2. Place the SPLIT phone at the intermediate timing line.
3. Place the FINISH phone at the finish line.
4. Aim each camera so the green vertical timing line crosses the athlete's path.
5. Use **ROLE** to correct a device assignment when needed.
6. Use **CAMERA: FRONT/BACK** before arming to select the usable camera.

<Tip>
  Camera switching automatically disarms the detector. Confirm the preview and timing line again before arming.
</Tip>

## Record a run

<Steps>
  <Step title="Wait for timing readiness">
    Outdoors, wait for GNSS to show `LOCKED` or `DEGRADED`. The screen also reports the selected camera, target and delivered FPS, and timestamp source.
  </Step>
  <Step title="Arm the phones">
    Tap **ARM** on all three camera phones, or tap **ARM DEVICES** on the DISPLAY device.
  </Step>
  <Step title="Run through the lines">
    Cross START, then SPLIT, then FINISH. Each detector disarms itself after its confirmed crossing and sends one timestamp.
  </Step>
  <Step title="Read the result">
    The FINISH phone calculates the split and total time and broadcasts the result. The DISPLAY device shows the same result and keeps up to 12 recent runs.
  </Step>
</Steps>

A result includes:

- Split time
- Total finish time
- Split and total uncertainty
- GNSS confidence or a visible Wi-Fi fallback label

## Test without running

Tap **MANUAL TRIGGER** once on each camera phone in START, SPLIT, FINISH order. Manual events use the same clock mapping and result pipeline as detected crossings.

<Note>
  Manual trigger validates device discovery, clock mapping, event exchange, sorting, and result display. It does not validate camera detection or physical timing accuracy.
</Note>
